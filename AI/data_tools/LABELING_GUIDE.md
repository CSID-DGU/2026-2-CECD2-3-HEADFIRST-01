# raw 발화 라벨링 기준표 (초안 v0.1, 2026-10-19)

`labeling.csv`의 후보 행에 사람이 정답을 붙이는 규칙. 멘토 모델의 학습 포맷(구청 민원 접수 NLU, INFORM/UNCERTAIN)에 그대로 변환되도록 맞췄다.
질문 있으면 notes에 적고 넘어간다. 애매한 건 혼자 결정하지 말고 모아서 같이 정한다.

## 0. 작업 흐름

1. 엑셀로 `labeling.csv` 열기 (utf-8-sig라 바로 열림). **자동 칸(cand_id~hint_matched)은 수정 금지.**
2. `url` 클릭 → 그 시점부터 10초쯤 듣기. `context_prev`(직전 문장)와 `raw_text`(후보 발화)를 실제 소리와 비교.
3. 사람 칸 7개 채우기: speaker_group, corrected_text, entity_type, gt_value, pattern_tag, usable, notes.
4. `pattern_hint`는 정규식이 붙인 **참고용**이다. 틀릴 수 있으니 확인 후 `pattern_tag`에 확정값을 적는다.
5. 행당 1분 목표. 한 영상 끝날 때마다 저장. 파일 이름은 바꾸지 말 것(재실행 시 라벨 보존 기준이 cand_id).

## 1. 먼저 usable부터 판단 (N이면 나머지 칸은 비워도 됨)

| usable | 경우 |
|---|---|
| **Y** | 참가자·청취자·시민 **본인**이 말한 발화이고, 정답(값 또는 "값 없음")을 확신할 수 있음 |
| **Y** | 값은 없지만 질문에 대한 **비정보 답**("아이 몰라요", "서부 서부", 딴소리, 되묻기) — 이진 분류의 "나머지" 클래스 예시로 쓴다 |
| N | MC·진행자·DJ·아나운서·내레이션·자막 읽는 발화 |
| N | 노래 가사 (제대로 전사됐어도) |
| N | 누가 말했는지 모르겠음 / 두 사람이 겹쳐서 분리 불가 |
| N | 전사가 심하게 틀려서 실제 발화를 못 알아듣겠음 |
| N | 값이 나오긴 했는데 자기 정보가 아님 (남 얘기, 노래 제목, 연도 설명 등) |

## 2. 사람 칸 규칙

### speaker_group
- `노인`: 60대 이상으로 보이거나 본인이 60세 이상이라고 말함
- `일반`: 그 외 성인 (아나운서·젊은 층 포함)
- 판단 안 되면 비우고 notes에 "연령 불명"

### corrected_text  (= 모델 입력. 가장 중요)
- 실제로 들리는 대로 **한글로** 적는다. 숫자도 들리는 대로: "칠십오입니다" / "일흔다섯이요" (whisper가 `75`로 썼어도 바꾼다)
- 추임새("아이고", "저기", "네")는 그대로 둔다. 패턴의 일부다
- 사투리도 들리는 대로 (표준어로 고치지 않음)
- 말 끊김·되풀이도 그대로 ("누구 언니냐면")
- 한 세그먼트가 답의 일부만 담았으면(답이 다음 세그먼트까지 이어짐) 이어 붙여서 적고 notes에 "다음 세그먼트 병합"
- usable N이면 비워도 됨

### entity_type  (질문받은 슬롯 또는 발화에 담긴 값의 종류)
| 값 | 뜻 | 멘토 슬롯 |
|---|---|---|
| `name` | 이름 | name |
| `age` | 나이만 말함 ("일흔다섯") | birth_date → **UNCERTAIN**으로 변환됨 |
| `birth_date` | 년생 또는 생년월일 ("오십삼년생", "음력 오월 초엿새") | birth_date |
| `occurred_date` | 어떤 일이 시작된 날 ("그저께부터") | occurred_date |
| `complaint` | 불편·민원 내용 서술 | complaint_type |
| (비움) | 값과 무관한 비정보 답, 되묻기 | 질문받은 슬롯이 있으면 notes에 적기 |

질문은 있는데 답이 딴소리면 entity_type은 **질문받은 슬롯**을 적는다 (예: "연세가?" → "아이 몰라요" = `age`, gt_value 비움).

### gt_value  (정답. 정규화 형식)
| entity_type | 형식 | 예 |
|---|---|---|
| name | 한글 성명 전체 | `이미자` |
| age | 숫자만 (세는나이 그대로, 환산 안 함) | `75` |
| birth_date | `YYYY-MM-DD`. 년만 알면 `YYYY`. 음력이면 뒤에 ` (음력)` | `1953-09-13`, `1950`, `1950-05-06 (음력)` |
| occurred_date | 계산 가능하면 `YYYY-MM-DD`, 방송 날짜를 모르면 들리는 상대 표현 그대로 | `그저께`, `지난주 목요일` |
| complaint | 들리는 대로 짧게 | `길이 패여서 넘어질 뻔함` |
| (비정보 답) | **비움** | |

규칙: **gt_value가 있으면 INFORM, 비어 있으면 UNCERTAIN**으로 변환된다. 그래서 "모르겠다"·"딴소리"·"나이만" 은 전부 비우거나 age로 둔다.
값이 두 개 나오고 번복했으면 **마지막 값**. 확신 없으면 비우고 notes에 후보 값 적기.

### pattern_tag  (어떻게 말했나. 여러 개면 `|`로)
패턴표 코드 그대로 쓴다. raw에서만 쓰는 추가 태그 4개가 있다.

| 태그 | 뜻 | 예 |
|---|---|---|
| `PLAIN` | 패턴 없이 값을 바로 말함 | "저는 칠십오입니다" |
| `NON-INFORM` | 질문에 값 없이 회피·딴소리 | "아이 몰라요", "서부 서부" |
| `REASK` | 되묻기 | "누구 언니냐고?", "네?" |
| `FIX` | 번호 아닌 값의 번복·교정 | "팔일 아니 구일이요" |
| `NM-L1-1` | 이름 글자풀이 | "박사 할 때 박" |
| `NM-L1-2`/`NM-L1-3` | 자모 설명 / 자모+글자풀이 혼합 | "시옷에 오 이응 받침" |
| `NM-L2-1`/`2`/`3` | 자음 / 모음 / 복합 교정 | "지읒이 아니라 치읓" |
| `NM-SP-1`~`4` | 두 글자 단어+글자 / 유사음 / 서류 표기 / 외자 | "허철인데 철이 외자예요" |
| `DA-1` | 연속 숫자 생년월일 | "오삼공구일삼요" |
| `DA-2` | 음력·초N | "음력 오월 초엿새" |
| `DA-3` | 나이+생일 | "올해 예순일곱이고 생일은 십이월 팔일" |
| `DA-4`/`DA-5` | 상대 날짜(어제·그저께) / (지난주 요일) | "그저께부터요" |
| `UN-1`/`UN-2` | 기억 안 남·띠만 / 아무거나·상관없음 | "양띠인데 몇 년이더라" |
| `CT-1` | 민원 내용 서술 | "길이 움푹 패여서" |

전화번호 패턴(NU-*, DS-1~5)은 raw에서 안 모으므로 나올 일이 거의 없지만, 나오면 그대로 적는다.

### notes
- 질문이 context_prev에 없을 때 실제 질문: `Q:연세`
- 병합·분리: `다음 세그먼트 병합`
- 확신 없는 값: `75 또는 76`
- 그 외 뭐든 자유롭게. 나중에 규칙을 고칠 재료가 된다.

## 4. 자주 나올 애매한 경우

- **나이를 "팔학년 삼반" 식으로 말함** → corrected_text 그대로, entity_type `age`, gt_value `83`, pattern_tag `PLAIN`, notes에 "학년 표현". (패턴표에 없는 노인 표현이라 따로 모아둘 가치 있음)
- **"구십 안 됩니다"처럼 범위만** → gt_value 비움(UNCERTAIN), notes에 범위.
- **MC가 대신 말해주고 참가자는 "네"만** → 참가자 발화는 값이 없으므로 N. (MC 발화는 어차피 N)
- **질문 없이 자기소개로 값을 말함** ("저는 마산 사는 김순조, 구십한 살입니다") → usable Y, entity_type은 값 하나만 고르고(이름 우선) notes에 나머지 값. 한 행에 값 여러 개면 `DS-3`처럼 다중 정보로 보고 notes에 전부 적기.
- **사투리로 값이 바뀜** ("일흔다섯이라예") → corrected_text 그대로, gt_value는 표준 값.
- **whisper가 숫자를 아라비아로 썼음** (`75`) → corrected_text에는 들리는 대로 한글. 이게 패턴 실험의 입력이라 중요.
- **같은 발화가 두 행에 걸쳐 있음** → 앞 행에 병합해서 Y, 뒤 행은 N + notes "앞 행에 병합".

## 5. 분담·검수

- 영상 단위로 나눈다 (한 사람이 한 영상 전체. 문맥 파악이 빨라짐).
- 각자 첫 20행은 채연이 검수해서 기준을 맞춘 뒤 진행.
- 끝나면 전체의 10%를 두 명이 겹쳐 달아 일치율 확인. gt_value·usable 기준으로 90% 밑이면 규칙을 고친다.
- 이 문서는 라벨링하면서 발견한 사례로 계속 고친다. 고친 날짜와 내용을 맨 아래에 적을 것.
